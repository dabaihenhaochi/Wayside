# v0.0.4：抵达后采集一块原木

NPC 自动寻找附近原木，走近后工作 40 个游戏 tick（正常速度约两秒），破坏一块原木并产生正常掉落物，清除目标后继续搜索。

## 代码分工

- `NpcFindBlockGoal`：寻找原木，并为它选择可到达的操作站位。
- `NpcMoveToTargetGoal`：走向操作站位；途中如果已经能安全采集，就停下工作。寻路失败时重新选择站位，同一原木更换站位不会重置总超时。
- `NpcHarvestBlockGoal`：抵达后计时，朝向原木、挥手并显示破坏进度，完成时破坏方块。
- `NpcBlockInteraction`：检查落脚处、身体空间、视线和操作距离，并筛选有完整可达路径的站位。
- `NpcEntity.canReachBlock`：让移动和采集共用上述检查。

原木位置 `blockTarget` 和脚底站位 `moveTarget` 分开保存。采集范围按眼睛到原木最近表面计算，最大 2.5 格，因此可以采集头顶和脚底高度以下、视线未被遮挡的原木。

站位需要完整顶面支撑、足够的身体空间，并避开液体；不会选择待采集原木本身作为支撑。NPC 正踩着原木时，先走到旁边再采集。当前站位搜索采用方块网格中的完整顶面，不处理半格高度的台阶等复杂落脚面。

站位搜索限制在原木水平三格、下方四格至上方两格的局部范围，优先选择留有操作余量的近处位置，每次最多尝试 32 条路径。没有合适站位或无法到达时，原木进入冷却，NPC 随后寻找其它目标。

NPC 生成或被推到空中时，等待落地再规划路径，不把暂时不能寻路当作资源不可达。自动采集站位使用精确路径目标，避免默认寻路容差使 NPC 提前一格停下；玩家手动移动保留原有到达距离。

采集只在服务端执行，遵守 `mobGriefing` 和 NeoForge 的生物破坏事件。目标消失或改变、NPC 离开操作范围、视线被挡或收到手动移动命令时，中断本次工作；重新开始采集需要重新计时。无法到达的目标继续使用现有超时与冷却机制。

本版不含背包和工具系统。掉落物留在世界中，每次只处理一个方块。

## 验证

在工程目录中运行：

```powershell
.\gradlew.bat build
.\gradlew.bat runGameTestServer
```

游戏内自动测试覆盖等待后采集、远处自主搜索与移动、目标消失、隔墙超时、工作途中新增遮挡、手动命令中断、连续采集、关闭生物破坏规则，以及头顶采集、低处采集、先离开脚下原木、为高处目标选择地面站位、拒绝悬空与低矮站位、拒绝不可达站位和移动途中目标消失的清理。

测试代码和场景位于 `src/gameTest/`，仅用于开发运行，不包含在发布 JAR 中。自动测试使用 `build/gametest/` 下的独立世界。

在 IDEA 中重新加载 Gradle 工程后运行客户端，可在平地生成 `wayside:npc`，并在附近放置原木观察动作、破坏进度和掉落。背包计划留到后续版本。

- `build` 成功，生成 `build/libs/wayside-0.0.4.jar`。
- 高度与站位改进后，`build` 与 `runGameTestServer` 成功，十五项游戏内行为测试全部通过。
- 已检查发布 JAR，不包含游戏测试代码和空场景模板。
- 尚未进行客户端画面的人工试玩，挥手、裂纹和声音效果可在 IDEA 启动客户端后观察。

本次命令行验证遇到了 Windows Java 临时连接路径问题（`Unable to establish loopback connection`），为当前进程指定工程内临时目录后正常运行。如果再次遇到相同错误，可在工程目录的 PowerShell 中使用：

```powershell
New-Item -ItemType Directory -Path build/java-sockets -Force | Out-Null
$socketDirectory = (Resolve-Path build/java-sockets).Path
$env:JAVA_TOOL_OPTIONS = ($env:JAVA_TOOL_OPTIONS + " -Djdk.net.unixdomain.tmpdir=$socketDirectory").Trim()
.\gradlew.bat build runGameTestServer --console=plain --no-daemon
```

该环境变量仅影响当前终端及其启动的进程，不修改系统环境变量。
