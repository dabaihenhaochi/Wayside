# NPC 垫脚施工与山边移动

`PillarUpAction` 完成一次原地垫高：移动到当前格中心、检查上方跳跃空间、正常跳跃、脚下放一块泥土、等待落稳。它不传送 NPC，也不关闭重力。

## 触发顺序

1. 优先查找普通可操作目标和可达站位。建筑放置受阻时使用 [隔空放置兜底](construction-placement.md)，不再为它安排垫高。
2. 对整地填土、清障等仍需实际靠近的操作，区分“存在有效站位，但路径不通”和“根本没有满足距离/视线/落脚条件的站位”。只有真实寻路失败或移动超时，才记为垫高候选；缺少支撑、权限拒绝、碰撞、失败冷却或仅仅扫描结束都不能单独触发。
3. 其他普通候选都不可执行，或严格操作的移动已经失败时，规划器只检查上述寻路受阻目标。有限原地垫高后必须能让其中一个目标直接进入操作距离和视线，才有必要垫高；不能解决的高墙、绕路或深坑不会盲目垫土。
4. 从当前脚下到有效高度所需的每一格泥土，都必须在当前任务的建筑/场地保护区之外，并且不与任何已登记建筑的预留空间相交。还须有稳定底座、足够上方空间、无液体、已加载且在世界边界内，并有足够的多余泥土。
5. 每次只执行一格 `PillarUpAction`。实际落块前持续重新检查区域许可；规划后新登记的建筑也能中止本次放置且不扣泥土。成功落稳后重新寻路和规划，连续垫高最多八格，完成一次正常施工后才重置计数。

执行器会预留当前施工计划仍需的泥土，并将预留数量传给垫高和单格放置动作。开始垫高时、临时写入前、放置事件回调后最终扣料前均检查库存，避免跳跃期间取走多余泥土后误用预留材料。区域许可同样在放置事件后再次检查；回调中新登记的建筑也能使本次写入回滚。用于地基或蓝图的泥土不能被垫脚消耗。找不到有用的垫高方案时沿用原来的等待、重试与失败处理。

## 类的职责

- `PillarUpAction`：一次跳跃、放置和落地的过程，不知道蓝图或任务阶段；执行调用方提供的动态落块许可。
- `PlaceBlockAction`：继续统一处理材料成本、背包扣除、权限事件、实体碰撞、临时写入和失败回滚。脚下放置入口仅供同包动作使用，并有专用的腾空高度和落脚检查。
- `InventoryOps`：继续提供物品计数与扣料方法；没有另写一套背包操作。
- `ConstructionAccessPlanner`：只读检查垫高是否有助于实际寻路失败的目标，检查整段所需柱体的许可；不修改世界、不扣材料。
- `ConstructionWorkSelector`：普通站位选择，并收集本轮真实寻路失败的严格操作。
- `ConstructionRecovery`：集中管理泥土预留、连续垫高次数、失败位置冷却、所有建筑的预留保护和垫高动作。
- `ConstructionExecutor`：推进普通施工或辅助动作，处理结果并重新规划。
- `NpcMovementSafety`：集中定义安全落差和末端微调的落脚检查。

## 山边寻路

NPC 导航的单次下降上限为一格，移动动作也检查完整路径的落差。导航结束后的末端位置修正，必须确认沿途有地面支撑，不能只因为目标处身体空间是空的就继续走。

这是对 NPC 主动导航的限制；外力推落、地面被移除等情况仍可能让实体下落。

## 当前范围

- 使用背包中的泥土，每垫一格实际消耗一个，遵守生物破坏规则和方块放置事件。
- 垫高区域需要稳定底座、足够的上方空间，并与至少一个施工目标存在可用的距离与视线关系。
- 不自动搭水平桥梁，不任意破坏周围地形，不保证可以从任意深度、任意远的位置返回山顶。
- 垫出的泥土柱会保留，避免拆掉 NPC 仍在使用的落脚点；自动回收以后再考虑。

验证（2026-10-29）：构建成功，80 项游戏内行为测试全部通过。包含单次垫高和真实落地、低顶判定、中途取消、事件拒绝、安全寻路、自动垫高恢复施工、泥土预留和无支撑目标保护。

连续垫高次数随建屋和整地任务的 `Execution` 数据保存。泥土已经放下、NPC 尚未落地时保存，也会计入本次垫高；暂停不会重复计数。旧存档没有该字段时从零恢复。泥土预留按剩余计划重算，失败位置冷却仅在当前运行期间保留。

寻路失败证据只在当前规划轮次保留；重新规划、暂停恢复或读档后需重新检查，不能拿旧失败记录触发垫高。已放下的泥土柱不会因为后来新增建筑预留而自动删除。

架构整理验证（2026-10-29）：构建成功，84 项游戏内行为测试全部通过，包含落地前保存、读档上限保护、旧数据兼容和背包交换/快照独立性。

触发规则调整验证（2026-10-29）：离线构建成功，102 项游戏内行为测试全部通过。新增覆盖真实寻路失败后的有效垫高、无几何站位不触发、当前场地与其他建筑的预留保护、未来柱体进入预留区时禁止开始、跳跃中新增预留时不落块不扣料、严格操作读档上限及整地泥土预留。此前正常视线优先与隔空放置兜底测试继续通过。尚未进行客户端人工试玩。

代码复查验证（2026-10-29）：先在旧逻辑复现提交时的库存/建筑预留变化及放置模式切换问题，再修复并通过全部 107 项游戏内行为测试。垫高许可改用不复制建筑列表的实时坐标查询，仍能观察到回调里新增的预留。
