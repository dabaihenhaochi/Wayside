# 层级任务与建造流程

## 现在的执行结构

```text
NpcTaskRunner                         只管理最外层任务的运行、暂停、取消、失败与重试
└─ BuildHutTask                       小屋参数，复用通用 BuildBuildingTask；初始化时读取蓝图
   └─ TaskSequence
      ├─ SITE: SelectBuildingSiteTask  分批搜索、检查施工入口、登记场地
      ├─ MATERIALS: PrepareBuildingMaterialsTask
      │  └─ SupplyMaterialsTask       材料齐备就成功；不足才规划内部子任务链
      │     └─ TaskSequence
      │        ├─ GatherResourceTask  需要外部原木时才创建
      │        └─ CraftRecipeTask …   按依赖顺序执行配方，直接调用移动与合成动作
      ├─ TERRAIN: PrepareBuildingSiteTask → ConstructionExecutor → 具体动作
      └─ CONSTRUCTION: BuildStructureTask → ConstructionExecutor → 具体动作
```

父任务可以继续放进更高层的 `TaskSequence`。例如未来的生存任务可以把建造房屋作为一个子任务，房屋任务继续分解成备料、整地和施工。当前没有实现农田、日常生活或完整的生存需求选择器；默认任务仍是建屋。

`EnsurePlanksTask` 每 tick 先判断木板数量，不足时调用“采集原木 → `CraftUntilExhaustedTask`”子链，目标达标就结束；不再为同一个合成动作增加目标专用包装类。它与“先采集十六根原木，再全部转成木板”的 `GatherAndCraftPlanksTask` 保留不同的停止条件。

## 三层职责

- **NpcTaskRunner** 管理最外层生命周期。不创建建筑、资源或工作台专用步骤。
- **Task** 判断自己的目标是否满足，并组合子任务，或在最末级直接调用 Action。
- **Action** 执行移动、破坏、放置、拾取或合成等具体操作。

`CompositeTask` 统一向当前子任务转发暂停与目标查询。它不选择业务、不规定步骤顺序。

`TaskSequence` 统一推进顺序：每 tick 只执行当前子任务，成功才进入下一步；失败保留当前位置并把原因向上传递。内层链没有完成，外层就不能越过它。没有向父链前插任务的机制。

## 延迟创建与数据传递

不依赖前序结果的链仍可传入 `List<NpcTask>`。需要读取前序结果时，使用具名步骤工厂：

```java
new TaskSequence("example:build",
        TaskSequence.step("SITE", () -> new SelectBuildingSiteTask(project)),
        TaskSequence.step("TERRAIN", () -> new PrepareBuildingSiteTask(project.site)));
```

这是建筑包内的用法示意。工厂只在轮到该步骤的 tick 调用，选址成功后才读取场地创建整地任务。查询目标、显示阶段、暂停、保存和加载不会提前创建后续任务。工厂只负责创建对象，实际操作留在任务的 `tick` 中。

`BuildingProject` 是本次建造的有类型上下文，只保存蓝图参数、维度、建筑身份和场地结果；不调度、不操作背包。建造子任务通过它传递结果。任务序列本身不认识这些建筑字段。

## 建造顺序与材料

实际顺序是**初始化时读取蓝图 → 选址 → 准备总材料 → 整地 → 施工**。蓝图读取是一项初始化操作，后面四项才作为任务链步骤。把备料放在选址之后，是因为地基泥土数量取决于选中的地形。

选址检查地形、占地、方块是否受支持及真实可达入口，不再因为库存不足而反复换场地。成功后保存并预留同一个场地。备料合并地基与整地后房屋的需求，材料未齐备前不允许整地。失败后补上缺料并明确重试，会继续原场地。

补给复用已有 `MaterialPlanner` 和真实采集、合成行为。目前可外部采集的原料仍限于橡木原木，已有库存可以抵扣其他需求；不支持获取的材料返回 `MISSING_INGREDIENT`，需要工作台却没有工作台则返回 `MISSING_WORKSTATION`。采集范围内找不到资源时沿用采集任务的间隔等待搜索，不凭空生成材料。

施工执行器继续负责现场差异、视线优先、失败后的建屋放置兜底以及严格操作的有限垫高。相关行为分别见 [施工放置](construction-placement.md) 和 [辅助移动](npc-access.md)。

## 暂停与保存

任务链保存当前索引和按步骤名区分的子任务数据。读档时先保留这些数据，等执行到该子任务时才恢复；连续读档而尚未 tick，也不会丢失深层进度。完成的步骤不会重新执行。

建造上下文与任务链一起保存，加载上下文之后再恢复子链。整地和施工按现场重算剩余工作，已经施工的部分不重复扣料。

补给与补木板保存最终库存目标。部分合成已经真实写入背包，因此暂停或读档后重新按库存规划剩余采集、合成，不重放旧配方次数。

最外层任务仍须在 `NpcTaskTypes` 注册，运行器才能通过 ID 读档；内层任务由父任务的步骤工厂重建，不要求逐个全局注册。具名步骤和顺序是存档结构的一部分，后续改动需要明确处理存档影响。

本次采用新的任务链和建造进度格式，不迁移旧的步骤列表、旧建屋阶段或 v0.0.6 阶段字段。旧建屋数据缺少上下文时明确报告无效目标，避免重新整地破坏已有建筑；背包与建筑登记仍使用原有保存机制。

## 本轮精简

选址任务直接维护分批搜索游标，移除了单独的搜索转接类。配方任务作为最末级任务直接调用动作，不再额外创建工作台和合成动作的包装任务。任务链将尚未实例化的读档数据保存在一份具名数据中，减少并行状态。

上一轮具名任务格式中保存的独立 `BLUEPRINT` 步骤会在加载时折算到新的步骤索引，保留既有施工位置。这不包含更早的建屋格式和 v0.0.6 阶段迁移。
