# Wayside v0.0.8：自动整地并建造小屋

新 NPC 创建时自带一份有限初始物资，默认建造任务自动读取小屋蓝图，选择附近场地，先平整地形，再逐块建造。无需玩家交材料、派发任务或执行建造命令。

## 使用

在附近有可步行地面的平地或缓坡生成一个新的 NPC：

```mcfunction
/summon wayside:npc
```

初始物资固定为橡木原木 16、橡木木板 64、橡木楼梯 64、泥土 64，由 `NpcInitialSupplies` 集中配置。NPC 服务端构造时创建带物资的背包，即使暂停 AI 或更换默认任务也自带物资。整地和建造只使用现有库存；读档、换任务或重试都不会补满。

## 执行顺序

1. NPC 创建时由 `NpcInitialSupplies` 初始化背包。默认建造任务等待落地后，加载 `wayside:test_house` 原版结构蓝图。
2. 分批检查附近水平八格、上下两格的候选建筑原点；优先检查距离较近的位置。
3. 检查建筑占地、地基支撑、世界边界、已加载区块和已有建筑预留区域。低处最多连续补两层泥土，连续地层最多挖两层；过深坑洞、液体、方块实体和不可破坏的阻挡会使候选地块被拒绝。
4. 合并计算场地泥土和整地后房屋的材料。预算不足时继续找其他场地，不先破坏现场，也不依赖未来的掉落物抵扣预算。
5. 检查至少一个可达施工入口，登记建筑及其地基预留空间。
6. 执行 `PrepareBuildingSiteTask`：清理建筑包围盒内的阻挡，并从有支撑的底层开始补泥土。每次操作重新检查现场，沿用移动、破坏、放置动作。
7. 只有整个场地准备成功后，才启动 `BuildStructureTask` 放置房屋方块。房屋施工继续根据实际蓝图差异计算剩余工作。
8. 保存选中的场地、整地/建屋阶段、维度和背包。读档后继续剩余工作，不重新选址，不重复补发材料。

地面已有完整支撑会保留，不为了统一成泥土而拆掉石头。计划中的填土位置若已经获得可靠的实心支撑，也无需再次拆换；这也避免泥土变成草方块后被重复施工。

## 模块职责

- `BuildingSitePlanner`：只读地形，产生候选位置与土方计划；不接触 NPC 背包，不执行动作。
- `BuildingSitePlan`：保存场地净空、填土坐标和维度，按当前世界计算剩余整地工作；不认识任务运行器。
- `PrepareBuildingSiteTask`：提供整地工作计划并保存场地，复用通用施工执行器。
- `BuildStructureTask`：加载任意受支持的蓝图，提供蓝图差异计划，保存建筑身份；不负责选址或填土。
- `ConstructionExecutor`：两种任务共用的内部动作循环，管理移动、破坏、放置、失败处理和暂停；不认识小屋蓝图、初始物资或选址策略。
- `ConstructionWorkSelector`：排序、支撑检查、失败冷却和操作站位。房屋先做底层，再留出屋顶施工视线；地基填土采用从低到高且下方有实地支撑的顺序。
- `NpcInitialSupplies`：集中配置出生物资并创建独立背包，不依赖任务。
- `NpcEntity`：构造时取得初始背包，读档时用保存的完整库存替换默认值。
- `BuildHutTask`：编排当前小屋场景的选址、整地和建屋阶段，只读取库存，不发放材料。
- `BuildingSiteSearch`：封装 NPC 的候选遍历、总材料预算、入口预检和场地登记，独立于阶段编排。
- `ConstructionPlanner`、`BuildingMaterialCalculator`、`BlockPlacementRules`：共用差异和材料规则。预算可使用整地后的预期现场，不需要提前修改世界。
- `BuildingManager`：登记建筑时一并预留地基，避免其他建筑从下方占用或挖掉基础。
- `NpcTaskRunner`：继续只管理任务生命周期；通过工厂注入默认任务。没有增加建筑专用的 Minecraft Goal。

旧自动建屋存档如果只有 `Construction` 而没有整地阶段，直接恢复原来的房屋施工，不会读档后清空已经建好的部分。历史任务仍按原类型恢复。只要存档存在背包字段，就完整恢复其内容，包括空背包；旧的初始物资发放标记不再决定是否补发。没有背包字段的初始召唤 NBT 保留构造时的默认背包。

## 当前范围

- 目标是单个 NPC 用现有材料在平地或缓坡完成小屋，不接入补料、仓储或玩家交互。
- 填土只使用泥土，只调整建筑占地范围；不任意挖掘区域外通路、不架桥、不填深谷、不搭脚手架。
- 选址的可达入口检查不等于证明后续所有站位永远可达；每次操作仍需重新寻路。没有合适场地或长期无法施工时明确失败。
- 支持原版结构 `.nbt`，不读取 `.litematic`。普通单格方块及支持的复合数量状态共用材料规则；门、床等多格放置、方块实体数据和含液体状态仍待实现。
- 整地和建屋共用生物破坏规则及破坏/放置事件。放置被拒绝时保留材料，并撤回该动作的临时方块。
- 场地和施工任务绑定维度，避免跨维度后在同坐标误施工。

## 包结构整理

通用任务基础保留在 `entity.task`，建筑任务及内部辅助类进入 `entity.task.build`，采集、合成和备料任务进入 `entity.task.resource`。单个坐标的施工数据更名为 `ConstructionOperation`。采集专用操作移出通用任务接口，旧资源阶段转换移入对应业务任务。任务 ID 和存档字段保持兼容。

完整目录与阅读顺序见 [代码结构说明](code-structure.md)。

本次包整理验证（2026-10-29）：构建成功，64 项游戏内行为测试全部通过，包含旧合成阶段恢复和通用序列职责检查。

## 修改出生物资

修改 `entity/inventory/NpcInitialSupplies.java` 的物品列表即可调整物品种类和数量。每个 NPC 创建自己的物品堆，修改一个 NPC 的数量不影响其他 NPC。背包格数定义在 `NpcEntity.INVENTORY_SIZE`。

新增或修改物资配置只影响新创建的 NPC；已有存档恢复原库存。建造任务已经移除发放物资的方法调用、初始物品常量和相关背包空间判断。

初始物资职责调整验证（2026-10-29）：构建成功，70 项游戏内行为测试全部通过，包含未运行任务时的库存、召唤 NBT、刷怪蛋创建、精确读档、空旧背包及 NPC 库存独立性。
