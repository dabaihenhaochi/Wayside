# 施工顺序与放置兜底

建筑不识别楼层、屋顶或房间。施工选择器按蓝图坐标和方块类型安排工作：

1. 清除与替换阻挡，拆除从高往低。
2. 主体放置从低往高；同高度按 Z 逐行扫描，X 随行交替方向。
3. 火把、植物、按钮/拉杆、梯子、藤蔓、地毯、灯笼等常见依附方块最后补。

排序是尝试优先级。缺少真实支撑的方块会暂时跳过，现场变化后重新检查，不强行悬空放置沙子或依附方块。多格方块、方块实体等已有材料适配限制仍然适用；此改动没有新增门、床等方块的处理器。

施工执行阶段每 tick 最多进行一轮昂贵站位搜索（内部仍限制最多 32 次路径尝试）；廉价候选检查上限仍为八项。预算耗尽时保留当前候选，下一 tick 继续，不丢弃任务或重新扫描整份计划。选址入口预检保持原有预算。寻路失败项按坐标保存，避免反复线性去重。

## 正常放置优先

- 当前站位满足正常距离、视线和落脚检查时，使用原来的 `PlaceBlockAction`。
- 当前站位不满足时，先查找能够正常放置的安全可达站位，最多尝试移动 60 tick（正常游戏速度约 3 秒）。
- 找不到正常站位时，若水平距离超过 4 格，先尝试移动到目标 X/Z 对应的当前高度附近；移动失败或超时不阻止本次放置兜底。
- 没有正常站位、正常移动失败/超时，或实际放置时距离/视线失效，建筑执行器才调用 `PlaceBlockAction.constructionFallback`。移动途中恢复正常操作条件时，仍优先普通入口。

恢复普通放置时同步更新工作状态；若实际落块前视线再次丢失，仍能立即切回兜底，不会因残留模式标记进入额外冷却。

隔空放置不限制垂直手长，也不要求视线无遮挡。靠近只是尽力执行的行为，不是硬性放置前提；目标 X/Z 无法接近时，可能从较远处完成建造。这是本次选择的游戏化取舍。

## 共用事务

兜底只放宽距离和视线。仍检查已加载目标、世界边界、目标为空、方块适配、物理支撑、实体碰撞和材料数量。原有生物破坏权限与放置事件仍生效。

正常放置与兜底共用同一个事务：临时写入、触发事件、确认状态、重查调用方的区域许可和预留库存、精确扣料、成功后同步；拒绝或扣料失败时撤销仍由本动作持有的临时方块。已完成方块不会重复收费。普通、脚下与建筑兜底三种放置模式使用互斥枚举，避免布尔组合含义不清。

只有建筑的 `PLACE` 操作使用兜底。整地填土、拆除和采集不会因此获得隔空操作权限；选址入口预检也仍要求真实可达入口。

建筑放置的移动失败直接进入本节的隔空兜底，不进入垫高。整地/清障只有真实寻路失败且垫高可改善操作条件时，才使用 [建筑保护区之外的垫高恢复](npc-access.md)，两种补救不会为同一个建屋放置目标轮流触发。

## 暂停与读档

任务 ID、建筑身份、背包和旧 `Execution` 字段保持兼容。暂停/读档后重新读取现场与剩余材料，重新尝试普通站位，不保存陈旧路径或重复放置。旧垫高计数仍可读取，但不妨碍放置兜底。
